I want to develop a python package that helps me create cards.
The package should be a library that generates a deck of cards from a set of configuration files (.yaml), and a web application running locally to help users to create and manage their cards and decks.

# Main Features:

- Format and configuration: Let the user select between a huge amount of configurations for the cards and decks.
- Deck generation: Given a configuration file, generate a deck of cards in .pdf by using latex templates.
- Visual interface: Allow the user to create the configuration files through a visual interface.


## Layout

A layout is a set of parameters that define the position and size of an element inside a card. For instance, the background image, text, icons, etc.
A layout can have other layouts inside. Finally, the last layout is the card itself, made by the composition of all the layouts inside.
The layout will be defined in a configuration file, and it will be used to generate the cards in the deck.

### Parameters

Each layout has a rectangle associated to it, that defines the size and position of the layout inside the card.
The rectangle will be defined by its size (absolute or relative) and its position (absolute or relative to the card or the parent layout).
So, every size and position may be relative to the card, to the parent layout, or absolute. For instance, the background image will be relative to the card, while a text may be relative to the parent layout (for instance, a text inside a container layout).

There are different layout types:

- Image: use an image as the element
- Text: use a text as the element
- Color: use a color as the element
- Container: contain other layouts
- Bleed: lines that indicate the bleed of the card, that is the extra space around the card that will be cut after printing.

Different types of layouts may have different parameters. For instance, an image layout will have a parameter whether the image is cropped, scaled, etc. , while a text layout will have a parameter for the font, font color, font size, etc.

Layouts are only templates, do not have values associated.

## Card

A card will be tangled to a layout of the card (that has other layouts inside), and to specific values.
This is, a layout may be an image or a text, but the actual image or text depends on the card, and not on the layout.

This will be set in the configuration file, where, by id, a card will select a layout, and will give values to each individual layout inside the card layout also by id.

### Background

Each card may have a background image.
This means the layout of a card must allow 2 sides.

## Deck

A deck is a collection of cards. It will be generated by a configuration file with several card configurations.
Some cards can be repeated, so the configuration may allow to set the number of copies of each card in the deck.

There may be some parameters that are not set for a layout or card, for instance the actual size of a card, that may be all relative.
The deck may set these parameters global for all the cards in the deck.
Inside a deck there may be sub-desks, that are cards that share this kind of information.

For instance, I may want to create 10 small cards with layout A, and 10 big cards with layout B. I can create a deck with 2 sub-decks, one for each type of card, and set the size of the cards in each sub-deck.
